# mnemos-backend

The Python services: API, ingestion worker, realtime gateway, and the migration job.
All four are the same image with a different command.

```
src/mnemos/
├── core/          config · errors · logging · clock · ids · shared vocabulary
├── platform/      db engine · redis · (M5) objectstore · events
├── features/      identity · memory · retrieval · context · knowledge ·
│                  connectors · datasources · chat · tools · prompts · observability
├── flows/         rag · nl2sql · agent · router
├── entrypoints/   api · worker · realtime · cli
└── _v1/           the SQLite kernel, preserved verbatim until it is ported in M4
```

**Layering rule:** `domain` (pure) ← `application` ← `adapters`/`api`.
`features` must never import `flows`. A feature that needs a flow is a feature
that has been given the wrong responsibility.

## Local development

The stack is normally run with `docker compose up` from the repository root. To
work against it directly:

```bash
python3.12 -m venv ../.venv
../.venv/bin/pip install -e ".[dev]"

export MNEMOS_DATABASE_URL="postgresql+asyncpg://mnemos:mnemos@localhost:15432/mnemos"
alembic upgrade head
uvicorn mnemos.entrypoints.api.main:app --reload
```

Host port 15432, not 5432: the compose file remaps Postgres because a system
Postgres already owns the standard port on the development machine.

## Migrations

```bash
alembic upgrade head            # apply
alembic downgrade -1            # revert one revision
alembic check                   # fail if the models have drifted from the schema
alembic revision --autogenerate -m "what changed"
```

`alembic check` is the guard that matters. The models and the migrations are two
descriptions of one schema, and nothing but a check keeps them honest.

Revisions so far:

| Revision | What it does |
|---|---|
| `0001` | All 41 tables. Autogenerated from `mnemos.platform.models` |
| `0002` | Bitemporal `EXCLUDE USING gist` on `memory` + supersession-cycle trigger |
| `0003` | Monthly range partitions for `inference_call` |
| `0004` | `FORCE ROW LEVEL SECURITY` + org-isolation policy on 40 tables |

Anything a SQLAlchemy model cannot express lives in its own revision, so it can
be read and reverted independently of the table definitions.
