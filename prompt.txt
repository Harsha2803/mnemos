WHAT THIS PROJECT IS

An enterprise AI assistant. One conversation surface; a router (`A4`, scheduled *after*
`B1`/`B2`) will decide whether an answer needs documents (RAG, `A2`), a database (NL2SQL,
`A3`), a tool (MCP, `B3`), memory, or a combination. Underneath, every message will have an
inspectable, budgeted context bundle (`C4`) and a governed memory layer distinguishing
current facts from superseded ones (also `C4`) — the project's one deep technical claim,
measured on the v0.1 kernel and not yet re-measured on Postgres.

It is a portfolio project. Production practices, single-node scale, zero paid dependencies
in the default path, ever.

**Phase A is complete** (`A0`–`A3`, all ✅). "The thing this project is for" — sign in, talk
to it, ask about your documents, ask about your data — exists and is demonstrable end to
end. `B1` is the first step of Phase B: turning it from a chatbot into a platform, and is
already partway built on `feat/b1-connectors` (see above).

Sign in at http://localhost:3000 as org `mnemos`, then on Keycloak's form use
`analyst@mnemos.local` / `analyst` (or `user@mnemos.local` / `user`) — NOT
`admin@mnemos.local` / `admin` (TRACKER §4 item 40). If sign-in fails with an "already
belongs to a different subject" error after a fresh `docker compose down && up --build`, it
is Keycloak's own container config: `start-dev --import-realm` has no persistent volume, so
every full rebuild mints fresh subject UUIDs while the app's Postgres volume still points a
JIT-provisioned `app_user` row at the old one. Fix: `DELETE FROM app_user WHERE email = '...'
AND external_subject = '<the stale one, from the failing log line>'`, then sign in again —
disposable dev data, not a regression.

To ask a question about the data in the browser: open a chat session, select "Ask your
data" in the composer's mode control, and ask something about the seeded
`analytics.region`/`.customer`/`.sales_order`/`.product` tables.

Host ports (unchanged since M1): postgres 15432, redis 6380, api 8000, realtime 8001,
keycloak 8080, minio 9000/9001, ollama 11434. Python venv is at .venv/ in the repo root; the
package lives in backend/.
