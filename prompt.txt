WHAT THIS PROJECT IS

An AI workspace chatbot. One conversation surface; a router decides whether an answer
needs documents (RAG), a database (NL2SQL), a tool (MCP), memory, or a combination.
Underneath, every message has an inspectable context bundle and a governed memory layer
that distinguishes current facts from superseded ones.

Positioning: the app does many things. Context and memory management is the thing that
STANDS OUT among them, not the whole product.

It is a portfolio project. Production practices, single-node scale.

HOW TO WORK

Commits: one logical change per commit, conventional format. NEVER a bulk commit of
unrelated files. The commit message should say why, not just what.

Branches: work on a feature branch, never directly on main. The moment a branch has its
first commit, push it and open a PR (draft if unfinished) so no branch gets lost.
Check `git branch -a` and `gh pr list` at the start of every session.

Every change ends with ALL of:
  - pytest green            cd backend && ../.venv/bin/python -m pytest -q
  - alembic check clean     cd backend && ../.venv/bin/alembic check
  - TRACKER.md updated      status, next task, header
  - ADAPTATION.md updated   section 7 milestone position, section 8 current state
  - README numbers updated  ONLY if the retrieval or compile path moved, in which case
                            re-run the benchmark and paste the real numbers
