# Roadmap

**Last revised:** 2026-08-18

Mnemos is a portfolio project built to make the author's production experience legible to
reviewers and hiring teams. The roadmap therefore prioritizes a small number of deep,
demonstrable capabilities over completing every enterprise-product feature imagined in the
architecture documents.

Task-level scope lives in [ImplementationPlan.md](ImplementationPlan.md); live status and the
next executable brief live in [`TRACKER.md`](../TRACKER.md).

## 1. Finish-line strategy

| Stage | Milestone | Outcome | Why it matters |
|---|---|---|---|
| **Now** | `B3` — safe single-call MCP tools | Register, discover, approve, invoke, and audit one self-hosted tool with trust-tier denial | Shows current AI-tooling experience and security judgment. |
| **Next** | `C4` — governed context | Port bitemporal memory and the budgeted compiler to Postgres; expose `EXPLAIN` in the app | Lands the project's strongest and most differentiated technical claim. |
| **Finish** | reduced `D1` — portfolio release | Reproducible Compose startup, critical-path E2E, scripted demo, measured README | Makes the work easy to evaluate and every claim reproducible. |

After `D1`, the committed roadmap is complete. New scope should be added only in response to
interview feedback, real users, or a concrete role requirement—not because an old design
document contains another possible feature.

## 2. Scope decision

Four previously planned milestones are removed from the required finish line:

- `B4` multi-step agent orchestration is deferred; a reliable, gated single-call runtime is
  a stronger artifact than a broad agent loop with incomplete recovery semantics.
- `C1` API keys/full RBAC/tag ACLs is deferred; the built OIDC/JWT/RLS foundation and B3's
  live-role authorization already provide strong security evidence.
- `C2` prompt versioning/cost dashboards is deferred; it adds operations breadth but is not
  central to the portfolio thesis.
- `C3` conversation organization and expanded audit UI is deferred; it is conventional CRUD
  rather than differentiating engineering work.

The schema and architecture may retain seams for these capabilities. Retaining a seam does
not make the feature part of the committed plan.

## 3. Scope discipline

**One thesis.** The deepest claim is that context is a compiled artifact with provenance,
trust, exclusions, and a hard budget. Work that does not strengthen that claim, demonstrate
safe tool use, or make the project easier to evaluate is optional.

**Depth over breadth.** B3 and C4 receive production-style authorization, failure handling,
types, tests, persistence, and inspectable UI. Conventional features receive no speculative
implementation merely to increase the feature count.

**Cut features, never rigor.** A deliberately absent feature signals scope discipline.
Missing tests, unverifiable claims, leaked credentials, or silent failure paths signal weak
engineering and are never accepted as schedule shortcuts.

## 4. Non-goals for the portfolio release

| Non-goal | Reason |
|---|---|
| Multi-step autonomous agent loops | Deferred to `B4`; not needed to prove safe MCP invocation. |
| API-key product surface and exhaustive RBAC matrix | Deferred to `C1`; existing tenant isolation remains mandatory. |
| Prompt/cost management suite | Deferred to `C2`. |
| Conversation-product depth | Deferred to `C3`. |
| Kubernetes, Helm, Terraform, or multi-cloud abstractions | Compose is sufficient, reproducible, and free. |
| Paid models or required SaaS accounts | A reviewer must be able to run the full demo locally. |
| Benchmark chasing unrelated to governed context | Measurements serve the stated claim, not a leaderboard. |

## 5. Success criteria

The roadmap succeeds when a reviewer can clone Mnemos, run it without an API key, and verify:

1. authenticated multi-tenant chat routes safely across documents, data, and one MCP tool;
2. tool invocations enforce per-user credentials, approvals, live roles, and trust tiers;
3. every answer's context is compiled within budget and explainable in the UI;
4. security and correctness claims are pinned by focused tests and full-stack browser flows;
5. benchmark and README claims are generated by commands committed in the repository.

That is the finish line. Stars, feature count, and resemblance to a full SaaS product are not.
